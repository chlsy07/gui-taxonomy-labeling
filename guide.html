이 라벨은 "AI 에이전트가 과거 기억을 재활용할 수 있는가"를 측정하는 데 쓰입니다. 그래서 "화면에 뭐라고 쓰여 있나"가 아니라 "동작이 절차적으로 같은가"를 기준으로 나눕니다. 예를 들어 쇼핑몰의 장바구니 담기 버튼과 메일의 보내기 버튼은 글자가 전혀 다르지만, 둘 다 "보이는 버튼을 눌러 명령을 실행"이라는 같은 절차입니다. 그래서 같은 라벨(EXECUTE / command_button / click)을 받습니다.

화면에 뜨는 정보
① 스크린샷 — 빨간 원이 실제 클릭 좌표입니다. 우하단 돋보기가 그 지점을 3배로 확대해 보여줍니다.
② 과제 — 사용자가 원래 시키려던 전체 작업
③ 이번 액션 — 지금 이 한 동작에 대한 설명
④ 원본 코드 — pyautogui.click(x=0.44, y=0.25) 같은 실제 실행 코드

2. 반드시 지켜야 할 3가지

1

글이 아니라 화면을 보고 판단합니다

"이번 액션" 설명만 읽고 라벨하면 안 됩니다. 설명과 화면이 어긋나는 경우가 실제로 있고, 그럴 때는 화면과 클릭 지점이 이깁니다. 설명에 "메뉴를 연다"고 써 있어도 빨간 원이 체크박스 위에 있으면 체크박스입니다.

2

빨간 원이 찍힌 그 대상만 봅니다

주변 행 전체나 카드 전체가 아니라, 정확히 그 점에 있는 컨트롤이 대상입니다. 목록 행 오른쪽 끝의 작은 점 세 개를 눌렀다면 대상은 "목록 항목"이 아니라 "메뉴 열기 버튼"입니다. 확대(클릭 또는 z)해서 정확히 무엇 위인지 확인하세요.

3

버튼에 쓰인 글자를 라벨로 쓰지 않습니다

저장, 다운로드, 톱니바퀴, 햄버거는 라벨이 아니라 판단 근거입니다. 우리가 기록하는 것은 "무슨 글자인가"가 아니라 "어떤 형태의 UI 요소인가"입니다. 그래야 다른 앱의 비슷한 버튼과 비교할 수 있습니다.

3. TASK — 무엇을 하려는가

이 한 동작의 효과만 봅니다. 전체 과제가 "항공권 예약"이어도, 지금 검색창을 누르는 중이라면 TASK는 예약이 아니라 LOCATE입니다.

라벨의미예시
ACCESS메뉴·페이지·패널·설정·도구·대화상자를 열어서 접근 파일 메뉴 열기, 설정 페이지 진입, 사이드바 펼치기
AUTHOR텍스트·문서·콘텐츠를 만들거나 편집 메일 본문 입력, 문서에 문장 추가, 댓글 작성
CONFIGURE옵션·파라미터·설정값·권한을 변경 알림 끄기, 정렬 기준 바꾸기, 폼에 인원수 입력
EXECUTE실행·저장·전송·제출·적용·확정 등 명령을 발사 보내기, 저장, 결제, 검색 실행, 내보내기
INSPECT내용을 보려고 열기·선택·펼치기 메일 열어 읽기, 상품 상세 보기, 항목 펼치기
LOCATE검색·필터·이동·스크롤로 대상을 찾기 검색어 입력, 스크롤 내리기, 필터 적용, 탭 이동
ORGANIZE이동·정렬·그룹·선택·재배치로 구조 바꾸기 파일 드래그 이동, 항목 여러 개 선택, 순서 바꾸기
REFINE스타일·색·서식·크기·레이아웃 등 외형 다듬기 글자 굵게, 색 바꾸기, 이미지 크기 조정

ACCESS vs INSPECT

ACCESS는 나중에 일하려고 통로를 여는 것, INSPECT는 내용 자체를 보려는 것입니다. 설정 메뉴를 여는 건 ACCESS, 메일을 열어 읽는 건 INSPECT.

LOCATE vs EXECUTE

검색 버튼이라도 목적이 찾기면 LOCATE입니다. 저장·전송처럼 작업을 확정하면 EXECUTE.

AUTHOR vs CONFIGURE

입력한 글자가 콘텐츠로 남으면 AUTHOR, 설정·폼 값이면 CONFIGURE. 메일 본문은 AUTHOR, 인원수 입력은 CONFIGURE.

CONFIGURE vs REFINE

기능이 바뀌면 CONFIGURE, 겉모습만 바뀌면 REFINE.

4. TARGET FORM — 무엇을 누르는가

가장 어렵고 가장 중요한 축입니다. 글자가 아니라 형태, 그리고 지금 상태를 봅니다. 38개지만 그룹으로 나뉘어 있고 검색(f)이 되니 겁먹지 마세요.

버튼 / 명령

command_button글자가 있는 보통 버튼. 누르면 명령이 실행됨 저장, 확인, 검색, 장바구니 담기
icon_button아이콘만 있는 독립 버튼 돋보기 아이콘, X 닫기 버튼
toolbar_button툴바·리본 안에 들어 있는 버튼 워드 리본의 굵게 버튼

메뉴 — 위치와 단계로 구분합니다

top_level_menu_opener화면 최상단 메뉴바의 항목 파일, 편집, 보기, 도구
app_menu_button앱·브라우저 전역 메뉴 버튼 크롬 오른쪽 위 점 3개, 햄버거 ☰
menu_opener화면 안의 지역 메뉴 열기 목록 행 끝의 점 3개, 작은 옵션 버튼, 우클릭 메뉴 유발
submenu_opener이미 열린 메뉴 안에서 하위 메뉴를 여는 항목 "내보내기 ▸"
menu_item열린 메뉴 안의 실행 항목 열린 파일 메뉴의 "인쇄"
menu_item:on / :off체크 표시가 있는 메뉴 항목. 현재 체크 여부로 구분
메뉴 판단 순서 — ① 최상단 메뉴바인가 → top_level_menu_opener ② 앱 전체 메뉴인가 → app_menu_button ③ 이미 메뉴가 열려 있는 상태에서 누르는가 → 하위 메뉴를 열면 submenu_opener, 실행하면 menu_item ④ 그 외 화면 안에서 메뉴를 여는 것 → menu_opener

드롭다운 / 목록 — 열리기 전과 후는 다른 라벨

closed_dropdown_field아직 닫혀 있는 선택 상자나 그 화살표를 눌러서 여는 순간 "국가 선택 ▾"을 클릭
open_dropdown_item이미 열린 목록에서 항목 하나를 고르는 순간 펼쳐진 목록에서 "대한민국" 클릭
list_item드롭다운이 아니라 항상 떠 있는 목록·표의 항목 메일함의 메일 한 줄, 검색 결과 한 줄
같은 드롭다운이라도 여는 클릭과 고르는 클릭은 절차가 다르므로 반드시 구분합니다. 화면에 목록이 펼쳐져 있으면 open_dropdown_item, 아직 닫혀 있으면 closed_dropdown_field.

입력

text_input_field일반 텍스트 입력칸, 본문 편집 영역 메일 본문, 댓글창, 이름 입력칸
numeric_input_field값이 주로 숫자인 칸 인원수, 수량, 크기
search_box검색용 입력칸 — 글자를 받아도 검색이면 이쪽

상태가 있는 선택 — :on / :off

checkbox_option :on :off체크박스 ☑ ☐
radio_option :on :off라디오 버튼 ◉ ○ (여럿 중 하나만)
toggle_option :on :off토글 스위치
접미사는 누르기 직전의 현재 상태를 뜻합니다. 켜져 있는 걸 누르면 :on, 꺼져 있는 걸 누르면 :off. 같은 클릭이라도 현재 상태에 따라 결과가 정반대가 되기 때문에 구분합니다. 화면에서 상태가 안 보이면 접미사 없는 기본 라벨을 쓰세요. 추측하지 않습니다.

셀 / 문서 영역

cell스프레드시트·표·달력·격자의 칸
header_cell표의 머리글 칸. 누르면 정렬·행열 선택 같은 머리글 전용 동작이 일어남
document_text문서·편집기 안의 기존 텍스트를 대상으로 잡는 경우 문단을 드래그 선택
visual_region캔버스·이미지·빈 공간 등 뚜렷한 컨트롤이 아닌 영역

이동 / 시각 항목

navigation_entry사이드바·내비게이션 트리의 항목 받은편지함, 내 드라이브
tab탭 브라우저 탭, 설정 화면의 탭
link하이퍼링크
thumbnail_item썸네일·카드 형태의 시각 항목 템플릿, 동영상 카드, 슬라이드 미리보기

직접 조작

slider_handle슬라이더 손잡이
scrollbar_thumb스크롤바의 막대를 직접 잡아 끌 때
spinner_button:up / :down숫자 칸 옆의 ▲▼ 화살표. 방향까지 기록
드롭다운의 ▾ 화살표는 스피너가 아닙니다. 그건 closed_dropdown_field입니다.

마지막 수단

dialog_option대화상자 안의 옵션인데 위 어떤 형태에도 안 맞을 때. 정말 안 맞을 때만 사용하고, 메모를 남겨 주세요

5. ACTION — 코드에서 자동으로 정해짐

사람이 선택하지 않습니다. 원본 코드에 적힌 물리적 동작을 앱이 자동으로 넣습니다. 검색하려고 글자를 쳤어도 ACTION은 type이고, 찾는 의도는 TASK의 LOCATE에 기록됩니다.

click한 번 클릭
double_click더블 클릭
right_click오른쪽 클릭
drag누른 채로 끌기
scroll휠·트랙패드 스크롤
type글자·값 입력 (붙여넣기 포함)
press_enterEnter로 확정·검색·제출
hotkey키 입력·단축키 조합 Backspace, Space, Ctrl+C, Ctrl+V
terminate에피소드 종료. GUI 입력은 발생하지 않음
waitUI가 바뀌기를 기다림. GUI 입력은 발생하지 않음
원본 코드 읽는 법 — pyautogui.click → click, doubleClick → double_click, write/typewrite → type, hotkey('ctrl','v') → hotkey, press('enter') → press_enter, 그 외 press → hotkey, scroll → scroll, dragTo → drag, computer.terminate → terminate, computer.wait → wait.

6. DOMAIN — 어디에서 하는가

DOMAIN은 여러 단어가 동시에 떠오르는 태그가 아닙니다. 현재 타깃이 속한 화면 표면을 아래 순서로 검사하고, 처음 맞는 한 항목에서 멈춥니다. 이 순서가 12개 분류를 서로 배타적으로 만듭니다.

1. Security, Accounts & Credentials로그인·비밀번호·인증·계정 보안·권한 동의 화면. 어느 앱 안에 있어도 최우선
2. System, Files & OS SettingsOS 설정·탐색기·바탕화면·작업표시줄·OS 파일 열기/저장 창. 호출한 앱은 무시
3. Search, Browser & Maps브라우저 주소창·탭·설정·방문기록, Google/Naver 같은 범용 검색 결과, 지도·길찾기만
4. Documents & Productivity문서·표·슬라이드·메모·PDF·할 일·클라우드 드라이브 작업 화면
5. Communication, Social & Scheduling메일·채팅·회의·캘린더·SNS·연락처 화면
6. Commerce, Travel & Services상품·예약·여행·배달·채용·장바구니·결제·고객 서비스 화면
7. Media, Entertainment & Gaming영상·음악 소비, 스트리밍 탐색, 게임 화면. 제작·편집 화면은 제외
8. Developer, Cloud & Data코드·터미널·저장소·이슈·클라우드 콘솔·분석·노트북·LaTeX 화면
9. Research, Education & Reference학술 검색·논문·강의·학교·백과·참고자료 전용 화면. 범용 검색 결과는 제외
10. AI Assistants & GenerationAI 대화·프롬프트·생성 결과를 다루는 화면
11. Creative & Media Editing이미지·영상·음성·디자인을 직접 제작·편집하는 화면
12. General Web/App뉴스·블로그·회사 소개처럼 위 기능 도구가 아닌 읽기 중심 일반 정보 화면. 애매함용 라벨이 아님
검색은 동작이지 항상 Search DOMAIN은 아닙니다.
Google Scholar·arXiv·PubMed·위키백과 안에서 검색 → Research, Education & Reference
Amazon 안에서 상품 검색 → Commerce, Travel & Services
Google/Naver 통합검색 결과 → Search, Browser & Maps
“찾는 중”이라는 사실은 이미 TASK의 LOCATE가 기록합니다.

7. 자주 헷갈리는 경우

목록 행의 끝에 있는 점 세 개를 눌렀다

대상은 목록 항목이 아니라 메뉴를 여는 버튼입니다 → menu_opener. 라벨은 "무엇 안에 있나"가 아니라 "정확히 무엇을 눌렀나"로 정합니다.

메뉴가 열려 있고 그 안의 항목을 눌렀다

화면에 메뉴가 펼쳐진 상태면 그 안의 항목은 menu_item입니다. 화살표(▸)가 붙어 하위 메뉴가 나오면 submenu_opener.

선택 상자를 눌렀는데 목록이 안 보인다

스크린샷은 누르기 직전 상태입니다. 목록이 아직 안 보이면 여는 중이므로 closed_dropdown_field입니다.

체크박스인데 켜졌는지 꺼졌는지 안 보인다

확대(z)해도 안 보이면 추측하지 말고 접미사 없는 checkbox_option을 쓰세요. 잘못된 :on보다 정직한 무접미사가 낫습니다.

검색창에 글자를 입력했다

세 축이 각각 다릅니다 — TASK는 찾는 중이니 LOCATE, FORM은 검색칸이니 search_box, ACTION은 입력이니 type.

Ctrl+V로 메일 본문에 붙여넣었다

TASK AUTHOR(콘텐츠가 됨), FORM text_input_field(본문 입력칸), ACTION hotkey(코드가 단축키). 의도가 입력이어도 동작은 단축키입니다.

빨간 원이 아예 없다

키보드 입력이나 종료 동작이라 좌표가 없는 경우입니다. "이번 액션" 설명과 화면을 보고 어느 칸에 입력되는지 판단하세요.

정말 모르겠다

가장 가까운 라벨을 고르고 "애매함"에 체크한 뒤 메모를 남겨 주세요. 건너뛰면 정보가 0이지만, 애매함 표시된 답은 나중에 우선 검토 대상이 되어 쓸모가 있습니다.

8. 자주 묻는 것

모델이 붙인 라벨이 보일 때와 안 보일 때가 있어요
의도한 것입니다. 이미 의심스럽다고 분류된 항목은 모델 답을 보여주고 고치게 해서 시간을 아낍니다. 나머지는 모델 정확도를 공정하게 측정하려는 표본이라, 답을 보면 측정이 무의미해지므로 가립니다.
몇 개나 해야 하나요?
정해진 할당량은 없습니다. 하는 만큼 도움이 되고, 중간에 그만둬도 그때까지 제출한 건 모두 저장됩니다.
남이 이미 한 항목을 또 하게 되나요?
아닙니다. 앱이 서버에서 진행 상황을 읽어 아직 안 된 것만 배정합니다. 다만 일부는 일부러 두 사람에게 줍니다 — 사람끼리 얼마나 일치하는지 재기 위해서입니다.
실수로 잘못 제출했어요
되돌리는 기능은 없습니다. 대신 메모에 남겨 주시면 집계할 때 걸러낼 수 있습니다.
인터넷이 끊기면요?
라벨이 브라우저에 저장됐다가 연결되면 자동 전송됩니다. 오른쪽 위 표시로 상태를 알 수 있고, "내보내기"로 파일 저장도 가능합니다.
얼마나 걸리나요?
익숙해지면 한 건에 30초 정도입니다. ACTION은 자동으로 들어갑니다. 숫자키(TASK), f(형태 검색), Enter(제출)를 쓰면 더 빠릅니다.
